## 实现与兼容性

- 自动、手动、范围、工具与溢出整理共用 300 秒预算；排队、重规划、分块和
  合并不重新计时。正文和推理活动在完整缓冲前观察，心跳不延长预算。
- 摘要失败不再进入自动有损截断。可安全发送时继续原有效投影；硬上限或
  已确认溢出时结束尝试，保留具体摘要错误。删除不可达的截断写入实现，
  保留旧回执读取。
- 提交前取消拒绝安装；已接受提交完成持久化；多批部分成功如实标记。
  工作线程没有退出时保留所有权和恢复屏障。
- 进度通过可选事件、运行态与终态回执传递。手动操作保留原卡片与所有权；
  会话、运行 ID、epoch、revision 阻止串用和迟到事件重新打开终态。
- 重试只整理，服务端在准入边界校验失败身份。完成后不唤醒排队任务、收件箱
  或目标驱动器；不重放用户消息和工具。
- 新字段不进入模型请求，成功路径摘要提示词、schema、消息顺序及参数不变。
  旧记录可读；未知字段安全降级，旧远端不显示虚构的期限，握手校验未放宽。

行为和诊断字段见 [中文说明](../CONTEXT_COMPACTION_RECOVERY.zh-CN.md) 与

## 原生包验证

脚本：[compaction-native-smoke.mjs](../../desktop/packaging/compaction-native-smoke.mjs)。
使用 macOS arm64 实际 Electron 包、隔离 home、本地 SSE fixture 和生产 300 秒
期限；严格握手保持开启。目标场景包括停止、持续心跳、A→B→A、草稿与原始
消息保留、超时后重启、点击仅整理重试，以及 shell/service 正常退出。

最终原生脚本退出码为 0，以下断言全部通过：

- 点击输入框停止按钮后 SSE 关闭，原始消息不变；A→B→A 后停止入口仍可用。
- 连续心跳下，预算保持 `300000 ms`；终态观测时间距开始为 `300003 ms`，
  错误码为 `summary_budget_exceeded`，该次仅发出一个摘要请求，连接已关闭。
- 8 条原始 user/assistant 消息的 ID、顺序、内容在停止、超时、重启及成功
  重试后均保持一致；当前输入草稿在超时后及重启截图中保留。
- 重启后点击“重试整理”只增加一个摘要请求，普通对话请求数不变；完成后
  显示“上下文已整理，可以继续对话”，运行态为空闲。
- shell 与 Go 服务进程正常退出；没有残留 fixture SSE。

证据输出包括 `result.json`、`heartbeat-wait.png`、`timeout.png`、
`retry-after-restart.png`，由脚本写入指定证据目录。这些是本地测试产物，
不随仓库提交。等待及重启重试截图已人工检查。

原生点击补测发现初始会话代次 `0` 被 TabMeta 的 `omitempty` 省略，导致前端
无法关联可取消的运行态，停止按钮缺失。已明确传递初始代次，并补齐前端
取消中、恢复待处理阶段的合法状态解码；没有放宽会话身份选择规则。追加
序列化、状态选择及实际点击停止回归。切回静默整理会话时还需要立即广播新的
运行态绑定，不能只发送历史就绪通知而等待周期刷新；已在会话绑定成功后
补齐发布，追加 OpenSession 发布回归。最终 300 秒原生复验已通过。

最终包重编译 Go 服务和 CLI，前端复用此前完成完整 Electron 构建检查的同一
产物，并通过仓库既有产物摘要验证；严格协议握手未绕过。原生手动整理流程
没有设置任务时间预算，不把这个 fixture 当作所有自动溢出恢复、任务预算
组合的端到端验证；这些组合另由 Go 确定性和并发用例覆盖。
